# F6-T9 — System + Dashboard screens (BOC-08/09)

## Category
FE

## Objective
Operators see platform health, the audit log, entitlement configuration and a dashboard of
§149.18 operational counts, all read from existing/F6-T5 APIs.

## Scope
System (BOC-08, SUPER_ADMIN): Audit Logs — table with §90 columns (actor, role, action, entity
type/id, old summary, new summary, timestamp) and filters date range / user / module / entity
type (F6-T5 audit API); System Health — per-service readiness from F6-T5 health aggregation;
Feature / Entitlement Configuration — link/embed of F6-T7 free-tier + plan entitlement views;
Platform Settings — read-only list of existing config surfaces only ("not available yet" where none).
Dashboard (BOC-09, §149.18): counts for applications awaiting review, buildings by lifecycle
state, onboarding sessions needing action, active support sessions, plans by status — each card
links to its filtered list. Building and subscription counts come from F6-T7a/T7b; until those land the cards show
"not available yet", never a fabricated number.

## Dependencies
F6-T6, F6-T5; list APIs from F6-T7/T8.

## Implementation Requirements
No new metric beyond what source APIs return (BOC-09). Audit view is read-only.

## Acceptance Criteria
- Audit filters narrow results server-side; before/after summaries visible per row.
- Health view shows each service UP/DOWN with last-checked time.
- Dashboard numbers equal the totals of their linked lists.
- No GMV/MRR/ARR, live transaction feed, cluster map, cryptographic ledger/Merkle, DMP sync,
  or regulatory certificate panels (C-2; §149.18 revenue metrics deferred until billing exists).

## Test Requirements
Component tests for filters and card→list links; Playwright: dashboard → audit drill-down;
lint/typecheck/test green.
