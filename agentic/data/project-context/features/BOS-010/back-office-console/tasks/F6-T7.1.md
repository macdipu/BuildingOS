# F6-T7.1 — Building-application review screens (BOC-03, slice of F6-T7)

## Category
FE

## Objective
First bounded slice of [F6-T7](F6-T7.md): a platform operator lists building applications by
§149.4 status and reviews one application end to end, using the existing building-service
platform endpoints unchanged.

## Scope
- Buildings > Applications / Under Review: list via `GET /api/v1/platform/building-applications?status=`
  with status tabs named per §149.4 (SUBMITTED, UNDER_REVIEW, MORE_INFORMATION_REQUIRED,
  REJECTED, APPROVED) — not the mockup kanban (UI-INDEX C-3).
- Application review page (§149.5): applicant identity/contact, relationship, building
  details, verification documents, submission date, review history
  (`GET /api/v1/building-applications/{id}/history`), internal notes
  (`GET/POST /api/v1/platform/building-applications/{id}/notes`), duplicate matches
  (`GET /api/v1/platform/building-applications/{id}/duplicates`).
- Actions: Start Review / Request Information / Reject / Approve
  (`POST /api/v1/platform/building-applications/{id}/{start-review|request-information|reject|approve}`);
  approve form prefills the initial admin phone (D-12) and surfaces the creation-fee-not-recorded
  rejection (D-24/D-26) as a clear message.
- Calls go through the existing `/api/gateway/[...path]` proxy (`src/lib/gateway.ts`).

## Implementation Requirements
Reuse existing endpoints and payloads exactly as in `contracts/openapi/platform.yaml`; every
failed mutation shows the backend error code; `expectedVersion` conflicts (409) surface as a
refresh prompt. Layout from DESIGN.md tokens already in `globals.css`.

## Acceptance Criteria
- Operator moves an application SUBMITTED → UNDER_REVIEW → APPROVED / REJECTED /
  MORE_INFORMATION_REQUIRED with notes, and sees history + duplicate matches.
- Approve without a recorded creation fee shows the backend's rejection clearly.
- Nav items Buildings > Applications / Under Review render the real screens instead of
  `NotAvailable`.

## Test Requirements
Vitest component tests for the review actions (success, error code, 409 refresh prompt) and the
status-tab list; `npm run lint`, `npm run typecheck`, `npm test` green.

## UI Reference
- `ui/stitch/back-office/02-building-onboarding-pipeline` — table + side review panel layout.
- BRD §149.3–149.5. UI-only excluded: kanban stages, RAJUK/sub-registry KYC (C-3).

## Out of Scope
Building lists / lifecycle actions (needs F6-T7a), subscriptions screens (F6-T7.2 / F6-T7b),
assisted-onboarding assignment from the review page (F6-T8), Playwright flow (F6-T10).
