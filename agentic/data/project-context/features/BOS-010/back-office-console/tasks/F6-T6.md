# F6-T6 — `buildingos_backoffice_web` scaffold: auth + §149.2 nav shell (BOC-01/02)

## Category
FE

## Objective
A separate Next.js (App Router, TypeScript) web app where platform staff sign in with the
existing phone-OTP flow and see the §149.2 navigation, filtered by their platform roles.

## Scope
- New top-level `buildingos_backoffice_web/` (sibling to `user_app`), D-09.
- Auth: `POST /api/v1/auth/otp/start` + verify (existing auth-service), dev OTP per D-01.
  Access/refresh tokens held server-side in an httpOnly, SameSite=Strict cookie by a Next.js
  route handler; browser JS never reads the token. All API calls go through a server-side
  proxy that adds `Authorization` and forwards to the API Gateway (`BACKOFFICE_API_BASE_URL`).
- Route guard: decode `platform_roles` claim; a user with no platform role sees an
  "access denied" page and is signed out. Backend remains the authorization boundary.
- Nav shell (desktop-first): 260px left rail with the full §149.2 tree (Dashboard; Buildings;
  Users; Subscriptions; Support; System), header with signed-in phone + roles + sign-out.
  Sections render a "not available yet" placeholder until their task lands.
- Section visibility by role (from BRD §4.1 permissions; UI convenience only):
  SUPER_ADMIN all; PLATFORM_ADMIN Dashboard/Buildings/Users(read)/Subscriptions(read)/Support;
  SUBSCRIPTION_ADMIN Dashboard/Subscriptions; ONBOARDING_AGENT Support > Assisted Onboarding;
  SUPPORT_AGENT Support > Active Sessions/History. System visible to SUPER_ADMIN only.
- Design tokens: `ui/stitch/design-system/DESIGN.md` → CSS variables / Tailwind theme
  (colors, Plus Jakarta Sans + Inter, radii, spacing, card/table/badge specs).
- Tooling: lint, typecheck, unit tests (Vitest + Testing Library), `Dockerfile`, compose entry
  in `infra/local/compose.yaml`, gateway CORS not needed (server-side proxy).

## Dependencies
None (auth-service OTP + JWT already exist).

## Implementation Requirements
No business logic in the UI (BOC-01). No secrets in client bundles. Follow the FE persona
(`agentic/kit/agents/fe-agent/AGENT.md`).

## Acceptance Criteria
- OTP sign-in works against the local stack; token never exposed to client JS (cookie httpOnly).
- `SUPER_ADMIN` seed user (`01306999005`) sees all six sections; a user without platform roles
  is denied; expired/invalid session redirects to sign-in.
- Rail matches §149.2 labels and order exactly; unbuilt sections show "not available yet".
- Visual style uses DESIGN.md tokens (rail, header, cards, badges).

## Test Requirements
Unit tests for claim decoding, role→section map, proxy header injection; one Playwright smoke
(sign-in → shell) against the local stack; `npm run lint && npm run typecheck && npm test`.

## UI Reference
- `ui/stitch/back-office/01-multi-tenant-platform-overview-metrics` — rail, header, layout only.
- BRD §149.1–149.2, §4.1. DESIGN.md "Layout & Spacing" (desktop 260px rail, 12-col grid).
- UI-only excluded: flat nav items "API & Webhooks", "Documentation", top-level "Support" link,
  "Platform Overview" naming (use "Dashboard"), DMP/RAJUK banners.
