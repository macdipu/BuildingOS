# F6-T1 — back-office-service scaffold

## Category
DB/Integration

## Objective
Stand up the new `back-office-service` module: same shape as every other backend
service (Clean Architecture, Flyway, `platform-web` shared security/error/correlation,
health/readiness, gateway-routed), owning the F6-specific schema, with no business
use cases wired yet.

## Scope
- New Maven module `backend/back-office-service`, added to `backend/pom.xml`.
- `V1__back_office.sql`: `assisted_onboarding_session`, `support_session`,
  `elevated_approval_request` tables per TECH-SPEC.md's schema sketch.
- Standard package skeleton mirroring `subscription-service`'s layout (smallest
  existing service): `domain`, `application/port/{in,out}`, `infrastructure`,
  `presentation`.
- `application.yaml`: port 8080 internally (8084 on host per TECH-SPEC), JWT
  issuer/audience/jwk-set-uri config, DB datasource, Flyway, actuator
  health/readiness/info/prometheus.
- `Dockerfile` matching the other services' pinned `eclipse-temurin:17-jre-jammy` base.
- `infra/local/compose.yaml` and `infra/dev/compose.yaml`: add `back-office-service`
  (build, image, container_name, env, depends_on postgres, healthcheck), plus a
  `back_office_db` role in the postgres init scripts.
- `api-gateway`: new pass-through route group for `/api/v1/platform/backoffice/**`
  (no concrete endpoints exist yet — this task only wires the route, F6-T3/T4/T5 add
  the paths it forwards).

## Dependencies
ADR-F6-001 (accepted); TECH-SPEC.md; operator technical approval (recorded on
RUN-8AAD6211653349D5BB3702342862F437).

## Implementation Requirements
Follow docs/ARCHITECTURE.md exactly as the other services do: no framework imports in
domain, no repository access from controllers, ArchUnit rules extended to cover the
new module the same way building-service's are. No use case, controller, or endpoint
beyond a bare `/actuator/health/readiness` in this task — that is F6-T3/T4/T5's job.

## Acceptance Criteria
- `mvn -B -f backend/pom.xml verify` passes for the new module (empty domain, migration
  tests only).
- Fresh Flyway migration succeeds against a Testcontainers Postgres.
- `docker compose -f infra/local/compose.yaml up -d --build back-office-service`
  reaches `healthy` alongside the existing services.
- Gateway route exists and returns 401 for an unauthenticated request to any
  `/api/v1/platform/backoffice/*` path once F6-T3 adds a real one (this task only
  needs the route registered; verify with a placeholder path if none exists yet).

## Test Requirements
Flyway migration integration test (Testcontainers Postgres), ArchUnit layer test,
`ServiceMetadataController`-equivalent smoke test matching the other services'
`/internal/platform/info` pattern.
