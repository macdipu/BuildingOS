# F6-T8 — Users + Support + Assisted-Onboarding screens (BOC-05/06/07)

## Category
FE

## Objective
Platform staff manage platform roles, assign and track assisted onboarding, and run
auditable support sessions with elevated approval for high-risk scopes.

## Scope
Users (BOC-05, §149.2): Platform Users / Building Admins / Onboarding Agents / Support Agents
lists (role filter over F6-T2 list API via back-office-service), user detail (phone, platform
roles, building memberships summary, subscription via per-user endpoint), assign/revoke platform
role — SUPER_ADMIN only, reason required, confirmation dialog.
Support > Assisted Onboarding (BOC-06, §149.11): list/filter sessions (status, building, agent),
start session (building, agent holding ONBOARDING_AGENT, D-10 scopes multi-select, reason,
expiry ≤ max duration), detail with lifecycle history, agent actions start-work / await-customer
/ complete, operator complete/cancel; EXPIRED shown read-only. Entry point also from the
application review page (F6-T7) as "Assign Onboarding Agent" (§149.5).
Support > Active Support Sessions / Support History (BOC-07, §149.12): start session (target
user and/or building, ordinary D-10 scopes, reason, expiry), end session; high-risk scopes create
a pending elevated-approval request shown distinctly; approve/deny visible to SUPER_ADMIN only;
history shows actor, target, scope, reason, start/end.

## Dependencies
F6-T6; F6-T2 (done), F6-T3 (in progress in this run), F6-T4.

## Implementation Requirements
UI never grants scopes itself; all checks are server-side. No "impersonate" affordance anywhere.

## Acceptance Criteria
- Non-SUPER_ADMIN never sees role assign/revoke or approval controls; backend 403 still handled.
- Session create validates scope/reason/expiry inline and shows 400/409/422/503 messages.
- High-risk scope request never appears as an active grant until SUPER_ADMIN approves.
- Every session list row links to its audit trail (F6-T9 audit view filtered by entity).

## Test Requirements
Component tests for role gating, scope pickers, elevated-approval states; Playwright: start →
complete onboarding session; lint/typecheck/test green.

## UI Reference
- No Stitch mockup for Users or Support (UI-INDEX "No mockup"). Build from BRD §149.2,
  §149.11–149.12 using DESIGN.md table, badge (role badges), form and modal specs, and the
  list+detail layout of `ui/stitch/back-office/02-building-onboarding-pipeline`.

## References
REQUIREMENTS.md BOC-05/06/07; DECISIONS D-10, D-33; tasks F6-T2, F6-T3, F6-T4.

## Out of Scope
Customer-visible onboarding indicator in `user_app`; action relay under a session (F6-T4 API).
