# F6-T3 — AssistedOnboardingSession domain + API (BOC-06)

## Category
BE

## Objective
`back-office-service` owns `AssistedOnboardingSession`: a platform operator assigns an
`ONBOARDING_AGENT` to one building for a limited set of D-10 onboarding scopes and a
bounded time; the session moves through its lifecycle and expires automatically.

## Scope
- Domain: `AssistedOnboardingSession`, `OnboardingSessionStatus` (§149.11 statuses),
  `OnboardingScope` (D-10 onboarding scope enum), transition rules.
- Flyway V3: `lifecycle_transition` (audited status change per session; actor nullable
  for system expiry) + index for due-expiry lookups.
- Use cases (one package per action): `startonboardingsession`, `listonboardingsessions`,
  `getonboardingsession`, `startonboardingwork`, `awaitonboardingcustomer`,
  `completeonboardingsession`, `cancelonboardingsession`; shared lazy expiry.
- Outbound ports + token-relay clients: auth-service `GET /internal/users/{id}` (assignee
  must hold `ONBOARDING_AGENT`), building-service `GET /api/v1/platform/buildings/{id}`
  (building must exist).
- REST under the existing gateway group `/api/v1/platform/backoffice/**`:
  - `POST /api/v1/platform/backoffice/onboarding-sessions`
  - `GET  /api/v1/platform/backoffice/onboarding-sessions?status=&buildingId=&agentUserId=&page=&size=`
  - `GET  /api/v1/platform/backoffice/onboarding-sessions/{id}`
  - `POST /api/v1/platform/backoffice/onboarding-sessions/{id}/{start-work|await-customer|complete|cancel}`
- compose (local/dev): `AUTH_SERVICE_URL`, `BUILDING_SERVICE_URL` for back-office-service.
- OpenAPI contract entries.

## Rules (D-33, D-10, §149.11)
- Create: `SUPER_ADMIN`/`PLATFORM_ADMIN` only. Created as `ASSIGNED`, `started_at` = now.
- Assignee must currently hold `ONBOARDING_AGENT`; building must exist.
- `access_scope`: one or more D-10 onboarding scopes; reason required; `expires_at` in the
  future and at most `buildingos.onboarding.max-duration` (default `P30D`) after start.
- Assigned agent (still holding `ONBOARDING_AGENT`): `ASSIGNED|WAITING_FOR_CUSTOMER →
  IN_PROGRESS`, `IN_PROGRESS → WAITING_FOR_CUSTOMER`, complete.
- `SUPER_ADMIN`/`PLATFORM_ADMIN`: complete, cancel.
- Visibility: operators see every session; an agent sees only sessions assigned to them
  (others are 404); any other caller 403.
- An active session past `expires_at` is persisted as `EXPIRED` (system transition, no
  actor) before any read or change; changing an ended session is 409.
- Every status change (including creation) appends a `lifecycle_transition` row.

## Acceptance Criteria
- Operator creates a session; invalid scope/reason/expiry → 400; non-agent assignee or
  unknown building → 422; dependency down → 503 and nothing stored.
- Agent-only transitions reject operators (403) and other agents (404).
- Cancel is operator-only; complete by assigned agent or operator.
- Expired sessions report `EXPIRED` and reject transitions with 409.
- Every transition is recorded with actor and timestamps.

## Test Requirements
Domain unit tests; Testcontainers Postgres integration test with stubbed auth/building
services; `mvn verify` green for back-office-service.

## Out of Scope
Customer-initiated `REQUESTED` sessions and the customer-visible indicator in `user_app`;
relaying mutations under a session (action-relay pattern, F6-T4); audit read API (F6-T5).
