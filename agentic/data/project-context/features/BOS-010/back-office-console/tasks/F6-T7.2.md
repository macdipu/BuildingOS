# F6-T7.2 — Subscriptions screens (BOC-04, slice of F6-T7)

## Category
FE

## Objective
Second bounded slice of [F6-T7](F6-T7.md): back-office operators manage subscription plans,
the free tier, the building-creation fee, and a single user's subscription, through the
existing subscription-service platform endpoints unchanged.

## Scope
- Subscriptions > Plans: list / create / edit / retire
  (`/api/v1/platform/subscription-plans`, `/{planId}`, `/{planId}/retire`); §149.16 entitlement
  keys as structured fields, not marketing bullets; unknown keys rejected by the API are shown
  inline.
- Free tier / default entitlements (`GET/PUT /api/v1/platform/free-tier`), on the Plans screen.
- Building-creation fee (D-24): fee record (`/api/v1/platform/fees/{feeCode}`), recorded payments
  (`…/payments`), status (`…/status`), on the Plans screen or a Fees panel.
- Subscriptions > User Subscriptions: look up one user's subscription by user id and assign /
  change plan (`/api/v1/platform/users/{userId}/subscription`). The platform-wide list waits for
  F6-T7b (D-35) — show a lookup form, not a fabricated list.
- Subscriptions > Suspended / Cancelled: stays `NotAvailable` until F6-T7b.
- Calls through the existing `/api/gateway` proxy.

## Implementation Requirements
Payloads exactly as in `contracts/openapi/platform.yaml` (and the subscription-service response
records where the contract types data as `{}`); every failed mutation shows the backend error
code; version conflicts (409) surface as a refresh prompt; reuse `ApiErrorNotice` from F6-T7.1.
Role visibility per `src/lib/nav.ts`; backend authorizes every call.

## Acceptance Criteria
- Plan create/edit/retire round-trips; invalid/unknown entitlement keys shown inline.
- Free tier and creation fee can be viewed and updated where the API allows.
- Operator can look up a user's subscription and assign a plan.
- No SaaS revenue/collection metrics, auto-pay, invoices, VAT or dunning UI (C-2, §149.23).

## Test Requirements
Vitest component tests for plan form validation/error display, retire, and user-subscription
assign; `npm run lint`, `npm run typecheck`, `npm test` green.

## UI Reference
- `ui/stitch/back-office/03-society-subscriptions-billing` — plan cards + table layout.
- BRD §149.15–149.16, §149.23. UI-only excluded: revenue KPIs, auto-pay/direct debit, VAT
  invoices, MRR ledger export (C-2).

## Out of Scope
Platform subscription lists (F6-T7b), building lists (F6-T7a), Playwright (F6-T10).
