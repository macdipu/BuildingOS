# F4-T6 — Gateway, OpenAPI and event contracts; revenue-policy enforcement

## Category
BE (api-gateway, building-service, contracts)

## Objective
Publish every F4 endpoint through the gateway and the platform contract before mobile work
(F4-T7/T8) depends on it, with gateway/direct-service permission parity, and enforce the
approved UO-D04 entitlement policy (UO-11).

## Scope
- Gateway `building-api` route adds `/api/v1/buildings/**`, `/api/v1/me/buildings`,
  `/api/v1/me/properties`, `/api/v1/me/building-invitations[/**]`: pass-through for all methods,
  token required at the gateway, bearer token forwarded; building-service re-authorizes every call
  (no gateway-only permission logic, so gateway and direct calls get the same answer).
- `contracts/openapi/platform.yaml`: 27 operations / 20 paths (portfolio, invitations, members,
  floors, units, batches, ownership, history, transfer documents) with request schemas and the
  error codes each operation returns.
- `OpenApiCoverageTest` (building-service): every controller path+method must be in the spec.
- `check-contracts.py`: per-event Kafka data schemas (e.g. `ownership.transferred` v1) must be
  closed objects whose required fields are declared.
- UO-D04: units, membership and ownership are free foundations. No entitlement gate exists; an
  ArchUnit rule forbids `unit`/`membership`/`ownership` from depending on billing/entitlement
  types. `max_units`/`max_users` enforcement stays deferred until counting rules are specified.

## Acceptance Criteria
- F4 paths route through the gateway unchanged with the caller's bearer token; no token → 401
  without reaching building-service.
- Contract drift between controllers and OpenAPI fails the build.
- F4 flows succeed without subscription-service (tests point it at an unreachable address).
